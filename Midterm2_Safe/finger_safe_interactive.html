How the neural network works

The job. Look at one overhead photo and answer: how many fingers, 0 to 5? That makes it a 6-class classification problem. Nobody wrote rules for what a finger looks like; the network learned it from labelled examples.

Convolution. A filter is a tiny 3 × 3 grid of weights. It slides over the image; at each spot it multiplies the pixels under it by its weights and adds them up. The result is a feature map that is bright wherever the filter’s pattern appears, such as the edge of a finger.

ReLU and pooling. ReLU sets negative values to zero. Max-pooling keeps the largest value in each 2 × 2 block, halving the map’s size while keeping the strongest signals. One block is filter → ReLU → filter → ReLU → pool, and the network stacks four. Deeper blocks see bigger patches of the photo, so they respond to whole finger shapes rather than edges. (The maps above are this network’s real activations for a “3”.)

Deciding. Each of the 96 final maps is averaged to one number. A last layer weighs those 96 numbers into 6 scores, and softmax turns the scores into probabilities that sum to 100%.

Learning. The weights start random. For each training photo the network guesses, the loss measures how wrong it was, backpropagation computes how each of the 211,510 weights should change, and the optimizer (AdamW) takes a small step. Photos were randomly tilted (±25°), mirrored and colour-shifted so it couldn’t memorize them. 40 passes (epochs) later it scored 97.9% on 1,920 photos it never trained on.

Two lessons from the experiments. Grayscale stalled near 83% because finger shadows looked like extra fingers; colour (skin against the green pad) reached 97.9%. When the room lighting changed, accuracy fell to 90.5% until training added random colour shifts, which restored 97.9%.

On the safe. The model runs on the Arduino UNO Q in about 27 ms per frame. Its hardest number is 4, where a folded thumb can look like 3 or 5, which is why a number must stay on top at ≥ 80% for a full second before it counts.
